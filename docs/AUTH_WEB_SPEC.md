# OCS Hosted Web Authentication & Licensing Specification (PRD v1.10 Section 4.10)

## Overview
This document specifies the exact API and redirect contract between the **OCS Desktop Workstation App** (Electron) and the external **Hosted Web Authentication Portal** (`https://auth.churchocs.com`).

---

## 1. Web-Redirect Login Initiation Flow (Desktop → Web)

When an operator clicks **"Log In via Browser"** on the Desktop Login Gate, the Desktop App opens the user's system default browser with the following URL structure:

```http
GET https://auth.churchocs.com/login?state={CSRF_STATE}&app=desktop&redirect_uri=ocs%3A%2F%2Fauth-callback
```

### Query Parameters Sent by Desktop:
| Parameter | Type | Required | Description |
|---|---|---|---|
| `state` | `string` (48-char hex) | **Yes** | Cryptographic CSRF state token generated by desktop client (15-min TTL). |
| `app` | `string` | **Yes** | Constant `desktop` identifying client platform. |
| `redirect_uri` | `string` | **Yes** | `ocs://auth-callback` URL-encoded. |

---

## 2. Authentication Web Portal Implementation (Web Server Side)

The hosted web application handles:
1. Church Organization Sign-in (Email/Password, Google OAuth, Apple Sign-in, Magic Link).
2. License & Subscription Validation (Active Seat / Church Workstation entitlement check).
3. Generation of a signed session JWT or API token containing organization & license claims.

---

## 3. Deep-Link Redirect Callback (Web → Desktop)

Upon successful sign-in on the web page, the web page issues a browser redirect or window location update to the custom OS scheme:

```http
ocs://auth-callback?token={SESSION_TOKEN}&state={CSRF_STATE}&email={USER_EMAIL}&org={CHURCH_NAME}&tier={LICENSE_TIER}
```

### Redirect Parameters Expected by Desktop:
| Parameter | Type | Required | Description | Example |
|---|---|---|---|---|
| `token` | `string` | **Yes** | Signed session JWT / API bearer token. | `eyJhbGciOi...` |
| `state` | `string` | **Yes** | Exact CSRF state passed in Step 1. | `d4e5f6...` |
| `email` | `string` | **Yes** | Operator / Church Admin Email. | `lead_pastor@gracecommunity.org` |
| `org` / `orgName` | `string` | **Yes** | Licensed Church / Ministry Organization Name. | `Grace Community Church` |
| `tier` | `string` | Optional | Subscription tier (`standard`, `pro`, `enterprise`). | `enterprise` |

---

## 4. Desktop Validation & Security Handling

1. **CSRF Validation:** Desktop strictly checks `returnedState === pendingAuthState.state`. If state is missing, expired (>15 min), or mismatched, the callback is rejected with an explicit security alert and no session is created.
2. **Secure Credential Storage:** Tokens are encrypted via the OS Credential Store (macOS Keychain / Windows DPAPI via Electron `safeStorage`) and stored in `session.enc`. Plaintext tokens are NEVER stored in JSON settings.
3. **Grace Period (FR-13.5):** Cached tokens grant 72 hours of offline launch without requiring internet access. Background re-validation runs silently when internet is available.
4. **Mobile Companion Isolation (FR-13.7):** Mobile Companion does not receive tokens or logins; it pairs directly to the authenticated desktop controller over the local network.
